# Mob Battle 性能与并发规范

## 结论

本项目的性能方向是“降低每 tick 工作量、维护生命周期索引、分摊峰值、避免重复调度”，不是把 Minecraft 世界逻辑并行化。Minecraft 世界、实体、注册表、玩家库存、渲染状态和网络上下文都具有线程亲和性；错误并发会产生竞态、跨存档泄漏和不可复现崩溃。

## 线程边界

| 工作 | 允许线程 |
| --- | --- |
| 世界、实体、AI、库存、注册表修改 | 服务器线程 |
| 客户端世界、渲染、声音、屏幕状态 | 客户端线程 |
| Datagen 文件生成 | Gradle/Datagen 进程拥有的工作线程，禁止复用运行时对象 |
| 不可变几何、纯数值批处理、压缩或解析快照 | 可异步，但输入不得包含活的 Minecraft 对象 |
| 异步结果应用 | 必须切回对应游戏线程，并重新验证目标仍存在 |

不得在线程池中捕获 `Level`、`Entity`、`Player`、`ItemStack`、Registry Holder 或网络 `context` 后延迟访问。需要异步时，先复制为不可变值对象；返回结果时按 ID/UUID 重新解析并验证生命周期。

## 已落地热点

### 客户端 Gecko 动画

`ClientGeckoAnimationTicker` 使用实体加载/卸载生命周期维护候选身份集合，并在切换世界时清空。每 tick 只检查候选集合，不再扫描玩家周围 AABB，也不通过反射判断类型。

- 复杂度：从与附近全部实体数量相关的扫描，收敛为 `O(k)` 候选检查。
- 权衡：增加少量生命周期状态，必须保证 unload 和 world switch 清理。

### 服务端延迟任务

`ServerTickScheduler` 按服务器实例维护优先队列，以“到期 tick + 序号”稳定排序。

- 入队 `O(log n)`。
- 每 tick 只弹出到期的 `k` 个任务，`O(k log n)`；未到期任务不遍历、不复制。
- 同到期任务保持入队顺序。
- 非服务器线程调用时只做一次 `server.execute` 将“入队”切回服务器线程。
- `SERVER_STOPPING` / `SERVER_STOPPED` 清理状态，避免跨存档残留。

不得用 `Thread.sleep`、`Timer`、每技能一个线程或无边界 `CompletableFuture` 替代。

### TeamFight

空闲状态先做 `O(1)` 活跃标记判断，无活动战斗时直接返回，避免每 tick 进入昂贵队伍逻辑。活跃状态的更新和清理仍由服务器生命周期驱动。

### 区域重力场

`AreaGravityFields` 缓存固定半径、包围盒模板、实体谓词、粒子类型和球面采样点，并把 416 个球面点分成四个 tick 相位，每 tick 处理 104 个点。

- 减少重复几何和对象构造。
- 降低单 tick 粒子峰值，同时保持完整周期视觉密度。
- 按世界/生命周期清理活动重力场。

### 凋灵骷髅王召唤物

使用 UUID 集合维护拥有的召唤物，只解析已知候选，不再遍历世界全部实体。

- 查询从 `O(world entities)` 收敛为 `O(k summons)`。
- 失效 UUID 在解析时清理，防止集合永久增长。

### 网络回调

Fabric play 回调已经位于对应游戏线程。客户端和服务端接收器直接处理，移除了无必要的 `client.execute` / `server.execute` 二次排队，减少一帧或一 tick 级额外延迟与闭包分配。

## 优化顺序

1. 用 profiler、日志计数或可复现压力场景定位热点。
2. 删除无效工作：空闲早退、避免重复查询和重复对象。
3. 建立生命周期索引：load/unload 维护，tick 只遍历相关对象。
4. 选择合适数据结构：身份 Set、UUID Map、优先队列、缓存常量。
5. 分片非关键视觉工作，控制单 tick 峰值。
6. 只有纯计算仍然占用显著时间时才评估异步。
7. 任何异步优化必须有取消、生命周期、线程切回和压力测试。

## 禁止的“伪并发优化”

- 对世界实体使用 `parallelStream()`。
- 在工作线程调用实体 AI、伤害、传送、生成、移除或粒子发送。
- 每个技能创建线程、定时器或执行器。
- 以并发 Map 掩盖错误的跨线程世界访问。
- 把网络回调再次排队，造成顺序变化。
- 将每 tick 全量扫描放到后台线程，保留同等算法复杂度。

## 性能验收

- 基线与修改后使用相同实体数量、技能频率和运行时长。
- 分别记录 MSPT、客户端帧时间、GC 分配和队列/索引规模。
- 验证服务器停止、玩家断线、实体卸载和切换世界后状态归零。
- 压力测试未知或过期 ID、集中同 tick 调度、大量召唤物和重复 Payload。
- 构建、服务端运行和主菜单验证必须通过；涉及实际战斗表现时还需在独立测试世界验证技能时序和视觉密度。

优化结论必须同时报告收益、额外状态成本、最坏复杂度和未覆盖场景，不能只以“使用异步”作为性能证据。
